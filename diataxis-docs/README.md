# Diátaxis Documentation Framework

A systematic approach to technical documentation authoring.

---

## What is Diátaxis?

Diátaxis is a way of thinking about and doing documentation. It prescribes approaches to content, architecture and form that emerge from a systematic approach to understanding the needs of documentation users.

Diátaxis identifies four distinct needs, and four corresponding forms of documentation:
- **Tutorials** - learning-oriented experiences
- **How-to guides** - goal-oriented directions  
- **Reference** - information-oriented technical description
- **Explanation** - understanding-oriented discussion

## Quick Start

**The best way to get started with Diátaxis is by applying it** - to something, however small.

1. Read the [Four Types](#the-four-types) section below
2. Review the detailed guides for each type
3. Start applying it to your documentation immediately
4. Use [The Compass](./THE-COMPASS.md) when you're unsure which type to use

## The Four Types

The core idea of Diátaxis is that there are fundamentally four identifiable kinds of documentation, that respond to four different needs:

### The Four Types at a Glance

| Type | Purpose | Orientation | Example Question |
|------|---------|-------------|------------------|
| **Tutorial** | To learn | Learning | "How do I get started?" |
| **How-to Guide** | To accomplish | Goal | "How do I do X?" |
| **Reference** | To look up | Information | "What does X do?" |
| **Explanation** | To understand | Understanding | "Why is X this way?" |

### Understanding the Structure

The four types form a structure based on two axes:

- **Practical vs Theoretical** (doing vs understanding)
- **Learning vs Looking up** (studying vs reference)

```
                Learning
                   ↑
                   |
    Tutorials  |  How-to Guides
    -----------+----------
    Explanation|  Reference
                   |
                   ↓
              Looking up
```

## Quick Reference

### Quick Decision Tree

**User is learning + doing** → Tutorial  
**User is learning + understanding** → Explanation  
**User is looking up + doing** → How-to Guide  
**User is looking up + understanding** → Reference

### Type Characteristics

**Tutorials**
- Learning-oriented
- Step-by-step
- Complete project
- Concrete examples
- Assumes no prior knowledge

**How-to Guides**
- Goal-oriented
- Task-focused
- Prescriptive steps
- Assumes some familiarity
- Addresses common problems

**Reference**
- Information-oriented
- Complete and accurate
- Organized for lookup
- Descriptive
- Precise and unambiguous

**Explanation**
- Understanding-oriented
- Context-rich
- Discussion-based
- Explains why
- Shows relationships

## Core Principles

- **Use Diátaxis as a guide, not a plan** - It's a map to help you check you're in the right place, not a checklist to complete
- **Work one step at a time** - Improve iteratively, don't try to complete everything at once
- **Every step in the right direction is worth publishing immediately** - Avoid the temptation to complete large tranches before publishing
- **Don't try to work on the big picture** - Focus on small, concrete improvements

## What Diátaxis Solves

Diátaxis solves problems related to documentation:
- **Content** (what to write)
- **Style** (how to write it)
- **Architecture** (how to organise it)

## Benefits

- Serves the users of documentation by addressing their distinct needs
- Helps documentation creators and maintainers with a light-weight, easy-to-grasp framework
- Doesn't impose implementation constraints
- Brings an active principle of quality to documentation
- Helps maintainers think effectively about their own work

## How to Use This Documentation

1. **Start small** - Don't try to read everything at once
2. **Apply immediately** - Use what you learn as you learn it
3. **Iterate** - Come back to these guides when you need clarity

## Common Mistakes to Avoid

- ❌ Mixing types in one document
- ❌ Writing tutorial as how-to guide
- ❌ Writing reference as explanation
- ❌ Trying to complete everything at once
- ❌ Waiting for perfection before publishing

## Remember

- As soon as you feel you have picked up an idea that seems worth applying, try applying it
- Come back to these guides when you need more clarity or reassurance
- Iterate between your work and reflecting on your work
