# The Map

Understanding the structure of Diátaxis documentation.

---

## The Two Axes

Diátaxis organizes documentation along two axes:

1. **Practical vs Theoretical** (doing vs understanding)
2. **Learning vs Looking up** (studying vs reference)

These axes create four quadrants, each corresponding to one of the four types of documentation.

## The Structure

```
                Learning
                   ↑
                   |
    Tutorials  |  How-to Guides
    -----------+----------
    Explanation|  Reference
                   |
                   ↓
              Looking up
```

### The Practical/Theoretical Axis (Vertical)

**Practical (Top)**: Documentation that involves doing something
- **Tutorials**: Learning by doing
- **How-to Guides**: Accomplishing tasks

**Theoretical (Bottom)**: Documentation that involves understanding
- **Explanation**: Understanding concepts
- **Reference**: Understanding the system

### The Learning/Looking Up Axis (Horizontal)

**Learning (Left)**: Documentation for studying
- **Tutorials**: Learning how to do something
- **Explanation**: Learning why things are the way they are

**Looking Up (Right)**: Documentation for reference
- **How-to Guides**: Looking up how to do something
- **Reference**: Looking up what something is

## The Four Quadrants

### Top-Left: Tutorials
- **Orientation**: Learning
- **Purpose**: To learn
- **Characteristic**: Learning by doing
- **User state**: Following along, doing for the first time

### Top-Right: How-to Guides
- **Orientation**: Goal-oriented
- **Purpose**: To accomplish
- **Characteristic**: Looking up how to do something
- **User state**: Knows what they want, needs steps

### Bottom-Left: Explanation
- **Orientation**: Understanding-oriented
- **Purpose**: To explain and clarify
- **Characteristic**: Learning why things are the way they are
- **User state**: Trying to understand concepts

### Bottom-Right: Reference
- **Orientation**: Information-oriented
- **Purpose**: To describe the machinery
- **Characteristic**: Looking up facts about the system
- **User state**: Knows what they need, wants facts

## Relationships Between Types

### Adjacent Types Share an Axis

**Tutorials and How-to Guides** (top row):
- Both involve doing something
- Difference: Learning vs looking up

**Explanation and Reference** (bottom row):
- Both involve understanding
- Difference: Learning vs looking up

**Tutorials and Explanation** (left column):
- Both involve learning
- Difference: Doing vs understanding

**How-to Guides and Reference** (right column):
- Both involve looking up
- Difference: Doing vs understanding

### Opposite Types Are Most Different

**Tutorials and Reference**:
- Tutorials: Learning by doing
- Reference: Looking up facts
- Most different in purpose and approach

**How-to Guides and Explanation**:
- How-to Guides: Looking up how to do
- Explanation: Learning why things are
- Very different in orientation

## Using The Map

### To Understand Your Documentation

1. **Identify where each piece fits** on the map
2. **See what's missing** - Are you missing an entire quadrant?
3. **See what's confused** - Is something in the wrong place?
4. **See relationships** - How do your pieces relate to each other?

### To Plan Your Documentation

1. **Don't try to fill everything at once** - Work iteratively
2. **Start where you have the most need** - Use The Compass to identify
3. **Fill gaps over time** - Each quadrant serves different needs
4. **Let the structure emerge** - Don't force it

### To Improve Your Documentation

1. **Check placement** - Is each piece in the right quadrant?
2. **Check balance** - Are you serving all four needs?
3. **Check clarity** - Is it clear which type each piece is?
4. **Check relationships** - Do pieces link appropriately?

## Common Patterns

### Missing Quadrants

Many documentation sets are missing one or more quadrants:
- **Missing Tutorials**: Users struggle to get started
- **Missing How-to Guides**: Users can't accomplish specific tasks
- **Missing Reference**: Users can't look up details
- **Missing Explanation**: Users don't understand why

### Confused Types

Common confusions:
- **Tutorials written as How-to Guides**: Too prescriptive, not enough learning
- **How-to Guides written as Tutorials**: Too much explanation, not enough directness
- **Reference written as Explanation**: Too much context, not enough facts
- **Explanation written as Reference**: Too many facts, not enough context

### Imbalance

Common imbalances:
- **Too much Reference, not enough Tutorials**: Hard to get started
- **Too many Tutorials, not enough How-to Guides**: Hard to accomplish specific tasks
- **Too much Explanation, not enough Reference**: Hard to look things up
- **Too many How-to Guides, not enough Explanation**: Hard to understand why

## Remember

The Map is a tool for understanding and thinking about your documentation, not a strict template. Use it to:
- Understand what you have
- Identify what's missing
- See relationships
- Guide improvements

But don't use it to:
- Force everything into strict categories
- Create documentation just to fill quadrants
- Ignore the needs of your specific users
- Overthink the structure
